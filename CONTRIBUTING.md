# Contributing

Keep changes scoped to one delivery phase and include a short explanation of the user behavior they enable. Run the checks in the README before opening a pull request. Add tests for behavior and migration changes. Keep domain data and provider outputs typed; do not introduce generated code execution. Never commit credentials, local `.env` files, or fabricated screenshots and evaluation results.

Update `docs/architecture.md` when a design decision changes.

## Mandatory language policy

English is required throughout the repository and for all development communication. This includes source identifiers, comments, docstrings, type descriptions, UI text, API responses and errors, tests and fixtures, README content, technical documentation, architecture and verification reports, commit messages, pull request descriptions, progress updates, and development summaries.

Translate any existing Turkish prose encountered during development into professional technical English, preserving functionality and avoiding unrelated changes. Review the relevant files before claiming language compliance and run relevant tests after changes. Preserve legal attribution and proper names; Unicode punctuation and UI symbols are permitted.

This policy applies to all future phases. Repository instructions for coding agents are recorded in `AGENTS.md`.
